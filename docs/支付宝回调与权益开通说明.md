# 支付宝回调与权益开通说明

> 用途：P0 阶段用国内支付宝网页支付后，自动给用户开通命盘、问事、今年运势或年度会员权益。

## 1. 当前代码已经支持什么

当前后端已经预留支付宝异步通知接口：

```text
https://youshu-homepage.vercel.app/api/payments/alipay/notify
```

支付宝付款成功后，会向这个地址发送通知。后端会做三件事：

1. 校验支付宝签名。
2. 检查交易状态是否为 `TRADE_SUCCESS` 或 `TRADE_FINISHED`。
3. 根据订单里的 `userId` 和 `productKey` 写入 Supabase 的 `user_entitlements` 表。

写入后，用户再次登录或刷新页面时，前端会从 Supabase 读取权益，自动解锁对应产品并显示剩余次数。

## 2. 需要配置的服务端环境变量

这些都只放在 Vercel 后台，不展示给用户，也不要写进前端代码。

```text
ALIPAY_APP_ID=你的支付宝应用 App ID
ALIPAY_PUBLIC_KEY=支付宝平台公钥
SUPABASE_URL=你的 Supabase Project URL
SUPABASE_SERVICE_ROLE_KEY=你的 Supabase service_role key
```

注意：

- `ALIPAY_PUBLIC_KEY` 是支付宝平台公钥，不是你自己的应用私钥。
- `SUPABASE_SERVICE_ROLE_KEY` 权限很高，只能放在服务端环境变量里，不能以 `VITE_` 开头。
- 前端继续使用 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`，只负责登录、读取自己的报告和权益。

## 3. 支付宝订单里需要带什么

创建支付宝订单时，需要把业务信息放进 `passback_params`，推荐 JSON 字符串：

```json
{
  "userId": "Supabase 用户 ID",
  "productKey": "bazi"
}
```

`productKey` 目前支持：

```text
bazi       命盘报告
question   问事解惑
annual     今年运势
membership 年度会员
```

年度会员会自动写入多项权益：命盘报告 1 份、今年运势 1 份、问事 12 次、月度趋势 12 期、专属追问 12 次、历史归档长期保留。

## 4. 还没做的部分

当前只完成了“支付宝付款成功后的异步通知和权益写入”。要实现完整自动支付，还需要补：

1. 创建订单接口：前端选择产品后，后端生成支付宝订单。
2. 支付跳转页：把用户带到支付宝收银台。
3. 支付结果页：用户付款后回到网站，提示到账可能有几秒延迟。
4. 订单表：记录订单创建、支付成功、退款、关闭等状态。
5. 退款联动：退款后把对应权益标记为 `refunded` 或 `revoked`。

P0 可以先用这套结构跑小范围测试：人工创建或触发订单，确认支付宝异步通知能写入 Supabase 权益，再补完整收银台流程。
