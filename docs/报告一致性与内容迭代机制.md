# 有数 · 报告一致性与内容迭代机制

> 版本：2026-07-18（report-v3）
> 用途：沉淀「不前后矛盾」和「报告越来越准」的产品机制，供模型、报告、顾问质检和后续后台迭代共同使用。

## 1. 核心判断

有数后期真正的壁垒，不只是接入某个大模型，而是形成一套可复用、可质检、可迭代的解释系统。

要解决两个问题：

1. 同一个用户多次生成报告，不能每次都像重新认识一个人。
2. 报告不能只靠主观感觉调 Prompt，而要通过样本、评分、反馈和版本管理持续变准。

产品目标不是让模型自由发挥，而是让模型在确定性排盘、固定核心画像和稳定表达规则之上做解释。

## 2. 一致性机制：三层内容结构

### 2.1 固定命盘层

固定命盘层由确定性程序生成，不交给大模型猜。

包括：

- 出生日期、出生时辰、出生地、性别。
- 四柱、五行、十神、大运等排盘结果。
- 起盘时间、报告语言、报告类型。

规则：

- 模型不得重新排盘。
- 模型不得自行补全用户出生信息。
- 同一组出生信息对应的排盘结果应稳定一致。

### 2.2 核心画像层

第一次生成命盘报告后，需要沉淀一份用户的「命盘核心画像」。

核心画像不是完整报告，而是后续所有报告都要继承的稳定判断。

建议保存字段：

- 性格底色：例如谨慎、外柔内刚、重责任、喜独立。
- 用力方式：例如先观察后行动、适合长期积累、忌急躁。
- 事业倾向：例如专业型、策略型、资源整合型。
- 关系模式：例如慢热、重安全感、边界感强。
- 风险提醒：例如容易过度思虑、机会来时先否定自己。
- 表达禁区：用户明确反馈不准、反感或不适用的判断。

规则：

- 后续问事、今年运势和追问都必须引用这份核心画像。
- 新报告不能推翻已有核心判断，只能补充、细化或说明例外。
- 如果确实需要修正核心画像，必须生成「修正原因」，并保留版本记录。

当前 P0 实现：系统会从最近一份个人结构报告中提取「开篇判断 + 前三条稳定判断」作为一致性锚点，连同固定盘面标识一并传给后续生成。问事和年度报告只能补充、细化或说明例外，不能在没有证据时推翻它。

### 2.3 场景解读层

场景解读层用于回答用户当下的问题。

包括：

- 命盘报告：回答「我是什么样的人，我该怎么用力」。
- 问事解惑：回答「这件具体事，眼下该怎么看、怎么做」。
- 今年运势：回答「从起盘日起，未来完整 12 个月怎么走」。

规则：

- 每次生成前，必须带入固定命盘层和核心画像层。
- 场景判断可以变化，但人的底色不能变来变去。
- 如果用户问的问题与核心画像出现冲突，要解释冲突，而不是直接给相反结论。

## 3. 一致性锁

生成新报告前，应执行「一致性锁」。

输入：

- 当前排盘结果。
- 用户核心画像。
- 最近若干份报告的关键结论。
- 本次报告类型和用户问题。

输出要求：

- 不得与核心画像中的稳定判断相互矛盾。
- 不得与最近报告的关键结论明显冲突。
- 可以根据不同场景给出侧重点变化。
- 如需修正，必须说明「这是补充」还是「这是修正」。

示例：

- 稳定判断：用户适合长期积累，不适合频繁跳动。
- 问事问题：接下来半年是否适合换工作。
- 合格回答：不直接否定换工作，而是判断「换可以，但更适合先看岗位稳定性、能力复用度和团队确定性」。
- 不合格回答：一份报告说适合安定，一份报告说越折腾越有财。

## 4. 越来越准：四个评分维度

有数的「准」不只指玄学意义上的预测，而要拆成产品可评估的四个维度。

| 维度 | 判断标准 |
| --- | --- |
| 像不像我 | 用户是否觉得说的是自己，而不是模板话。 |
| 有没有用 | 用户看完是否知道下一步怎么做。 |
| 是否稳定 | 同一用户多次生成是否前后一致。 |
| 是否克制 | 是否避免恐吓、绝对化、过度承诺。 |

报告迭代不能只问「准不准」，要把用户反馈拆到这些维度里。

## 4.1 版本与回归检查

每次调整报告时，不只看一份新报告是否好看，还要对同一批样本做回归检查：

1. 同一出生信息生成个人结构、问事和年度报告，稳定判断是否一致。
2. 同一问题连续生成两次，开篇判断和建议方向是否一致，是否只是换词重复。
3. 三种语言是否保持同一份判断，不因翻译改变结论强弱。
4. 是否出现不必要的绝对化、恐吓、医疗、投资或法律暗示。

出现问题时优先修正固定标题、输出长度和规则顺序；只有规则稳定后才调整模型或温度。

## 5. 迭代闭环

### 5.1 建立黄金样本库

第一阶段先积累 30-50 个真实样本。

每个样本至少包含：

- 出生信息。
- 当前关注问题。
- 三类报告生成结果：命盘、问事、今年运势。
- 用户反馈。
- 顾问评分。

黄金样本库用于比较不同 Prompt、不同模型和不同报告结构的效果。

### 5.2 建立评分表

每份报告按 5 个维度打分：

- 命盘逻辑是否成立。
- 表达是否像一位克制、有经验的命理顾问。
- 是否给出具体行动建议。
- 是否有前后矛盾。
- 用户是否愿意截图、转发或付费。

低分样本先改规则，不急着换模型。

### 5.3 沉淀好句子和坏句子

好句子应该深入浅出，有判断，但不恐吓。

示例：

> 你不是没有机会，是太习惯在机会来之前先否定自己。

坏句子通常过度承诺、过度玄乎或空泛。

示例：

> 你今年必定发财。

后续要形成品牌语言库，让模型学习「有数」自己的表达腔调。

### 5.4 Prompt 版本化

每次调整 Prompt 都必须有版本号。

示例：

- `prompt_v1`：基础报告结构。
- `prompt_v2`：减少空话，增强具体建议。
- `prompt_v3`：增强命理顾问口吻。
- `prompt_v4`：加入一致性锁。

每份报告都应记录：

- `prompt_version`
- `model`
- `report_type`
- `language`
- `core_profile_version`
- `quality_feedback`

当前实现基线为 `report-v3`：

- 三类报告都有固定一级标题与二级标题，减少模型临场拼接结构。
- 个人结构报告负责建立稳定画像；年度和问事报告读取该画像作为内部锚点。
- 输出不使用 Markdown 表格、粗体或逐月流水账，减少“文字堆砌”感。
- 命盘加入「当下处境、内在拉扯」，问事加入「你现在卡在哪里」，年度加入「你正处在什么位置、你最关心的事」。
- 年度报告必须读取用户选择的关注主题，避免表单选择与最终内容脱节。
- 每个中心判断按「判断、结构依据、2-3 个可核对的现实表现、边界或动作」展开。
- 三类报告保留足够输出空间。高级感来自清楚和克制，而不是把内容压成短提纲。
- 可核对表现必须使用条件表达，不得编造输入中没有的具体经历，以免用虚假共鸣换“准”。

这样才能知道哪一版真的更好，而不是凭感觉乱调。

### 5.5 用户反馈闭环

报告后可以放轻量反馈入口。

推荐反馈项：

- 像我。
- 有启发。
- 太泛了。
- 说重了。
- 想继续问。

反馈不只是做客服，而是用于判断：

- 哪类产品最容易转化。
- 哪种表达最容易被分享。
- 哪些判断经常被用户否定。
- 哪些高风险主题需要更克制。

## 6. 短期落地版本

P0 阶段先做轻量版本，不追求一次做完整后台。

优先做：

1. 个人结构报告首次生成后，保存短版稳定画像与 `prompt_version`。
2. 后续报告生成时把固定盘面和短版稳定画像作为内部一致性锚点。
3. 报告表保留 `prompt_version`、`consistency_profile`、`core_tags`、`quality_feedback` 的扩展位置。
4. 我的报告按个人结构、年度节奏、一事分析分组与筛选，用户能回看同一条判断脉络。
5. 每次 Prompt 更新前后，使用黄金样本做稳定性、可用性和合规性回归检查。

这套机制比单纯继续美化页面更重要。页面是皮，一致性和越用越懂你，才是长期壁垒。

## 7. 后续数据表建议

后续可在 Supabase 中补充：

- `user_core_profiles`：保存用户核心画像。
- `report_feedback`：保存用户对报告的反馈。
- `prompt_versions`：记录 Prompt 版本说明。
- `quality_reviews`：记录顾问抽检和评分。

P0 不必一次全部开发，但从现在开始，报告生成逻辑要按这些字段预留。
